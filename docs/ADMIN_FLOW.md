# Admin Flow Story

Imagine an administrator starting their day with one goal: making sure the university and course information in the system is accurate and ready for students.

The admin opens the dashboard and lands in a quiet control room for the CRICOS data. From here, they can ask the system to refresh its information from the official government source, check what has changed, and decide which updates should become part of the live record.

When new data arrives, the system does not change anything automatically. Instead, it gathers the differences and presents them to the admin in a clear list called staged changes. This gives the admin a chance to review the updates side by side with the current information, making it easy to verify corrections, additions, or removals.

Once the admin is satisfied that the data is right, they approve the staged changes. The approved information then becomes the new official version for universities, programs, and locations in the system.

Throughout the process, the admin can also explore the raw government records and inspect field details, which helps them understand why a change was suggested and whether it should be accepted.

In short, the admin flow is like a trusted editor: refresh the source, review proposed updates, and approve only the changes that should become part of the published university data.
